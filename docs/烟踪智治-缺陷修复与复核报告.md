## 2. 复核中新发现的缺陷（4 项，已一并修复）

> 这些是"修完原清单、再跑真实链路"才暴露出来的**功能性**问题，全部会直接影响答辩演示。

### D-18 后端 RBAC `require_pages` 误用为 all-of，环卫角色拿不到工单 🔴 高

- **症状**：API 模式下环卫端工单池**恒为空**（`qa-ends` 的「环卫端：登录后出现工单」「环卫端：可接单」两条用例 FAIL）。
- **根因**：`backend/app/deps.py` 的 `require_pages` 是 all-of（缺任一即拒），而调用方几乎都是 `require_pages("a","b","c")` 这种"该接口被这几个页面共用"的写法。`/workorders` 要求 `dispatch-pool + dispatch-records + workboard`，而环卫角色只有前两个 → `401/403`。
- **实测**：`worker01` 请求 `GET /api/v1/workorders` → `AUTH_PERMISSION_DENIED（需要 workboard）`。
- **修复**：`require_pages` 改为 **any-of**（命中任一页面权限即放行），并整段写明语义与受害者。单页调用语义不变；只有本来被 all-of 误伤的多页调用恢复可达。
- **复核**：环卫角色 `GET /workorders` → 200；`/workorders/stats` → 200（22 单）；匿名请求仍 401。

### D-19 种子数据永远产不出"待接单"工单 🔴 高

- **症状**：即使修好 D-18，环卫端「可接单」列表仍为空 → "接单 → 到场 → 提交验收"闭环演示不出来。
- **根因**（两层，`backend/app/seed.py`）：
  1. 判定"前 3 条待接单"用的是**事件下标** `i < 3`，而 `events[0..2]` 的状态恰好是 `pending_review / pending_review / false_alarm`，都在上面的 `continue` 里被跳过 → **`pending` 分支是死代码**；
  2. `created_at` 沿用事件时间（几小时~几天前），而超时扫描 `orders.is_overdue`（30 分钟 SLA）会在**任何人第一次打开任务池时**把所有陈旧 `pending` 直接升级为 `timeout`。
- **修复**：改用**工单序号** `seq` 判定，并把前 3 张 `pending` 工单的 `created_at` 拉回 25 分钟内。
- **复核**：重新种子化后 `by_status` 含 3 张 25 分钟内的 pending；`qa-ends`「环卫端：可接单」→ **PASS（已接 GD2026000002）**。

### D-20 入口页匿名状态打出 6 个 401（无效请求 + 污染巡检） 🟡 中

- **症状**：`入口页 index.html` 巡检失败：`资源失败 401 api/v1/cameras?size=200`。
- **根因**：入口页是纯叙事页，却调用 `demo.init()`；API 模式下数据仓库会去请求 6 个受保护接口，而此时并没有管理员令牌。
- **修复**：`api/client.ts` 新增 `hasAdminToken()`；`stores/demo.ts` 的 `refresh()` 在**未登录时不打受保护接口**，直接用本地模拟数据（量级预设，页面数值依旧合理）；已登录场景照旧走后端。
- **复核**：入口页巡检 PASS，无 401。

### D-21 后端缺 `/admin/activity/summary`，管理端 20 页全部 404 🟡 中

- **症状**：管理端 20 个页面全部 `资源失败 404 api/v1/admin/activity/summary`（页面不白屏，但每条 404 都被巡检记为失败）。
- **根因**：该接口**只在 `backend-java/PlatformController` 里实现**；前端代理收敛到 8000 后，FastAPI 侧缺失。属选型收敛时暴露的清单缺口。
- **修复**：新增 `backend/app/routers/activity.py`，按 Java 版**同一响应结构**补齐（`{total, sources, latest[{source,actor,detail,created_at}]}`），数据源复用只增不改不删的 `audit_logs`，并在 `main.py` 注册。
- **复核**：`GET /api/v1/admin/activity/summary` → 200，`total=29`，`sources={admin:17, citizen:5, worker:7}`，与顶栏「三端同步 N」吻合。
