# 烟踪智治 · 网站产品与前端设计方案

版本：v0.1  
日期：2026-09-27  
状态：讨论稿，仅定义产品与前端体验，不包含代码实现

## 1. 方案摘要

烟踪智治不应只是一套管理员数据大屏，而应是一套连接信阳市民、环卫作业人员、区域治理人员和依法履职的执法人员的日常工作平台。产品严格控制为三个端：市民用户端、治理作业端、平台管理与执法协同端。Landing Page 是市民用户端的登录前首页，不单独计算为一个端。校园仅是可选试点场景之一，不是产品范围上限。

整体体验围绕一个核心原则展开：**每个治理结论都能回到证据，每个治理动作都能看到结果。**

申报书用于说明研究背景和现有算法基础，但网站的产品范围、信息架构和交互不受申报书目录约束。既有管理员端功能保留并重新组织，视觉上放弃通用的“蓝绿玻璃智慧城市大屏”，转向具有项目辨识度的“城市行为取证台”。

## 2. 产品定位

### 2.1 一句话定义

面向信阳市各县区、街道、网格和公共空间的扔烟头动作发现、证据复核、环卫派单、执法线索协同与区域治理复盘平台。

### 2.2 核心价值

- 对治理人员：缩短发现、核验和派单时间，保留完整操作依据。
- 对环卫人员：获得位置明确、证据清晰、可快速完成的移动工单。
- 对市民用户：了解治理规则、实名上报行为线索与环境问题并查看处理进度。
- 对执法人员：接收经过人工复核的线索，核对证据、规则依据、身份核验和申辩记录。
- 对管理者：发现重复发生点和时间规律，用数据调整设施、巡查和宣传。

### 2.3 产品边界

- 核心识别对象是连续视频中的扔烟头动作，而不是单张图片中的烟头目标。香烟、手部和行人检测是时序行为分析的组成部分，不是最终产品结论。
- 系统判断的是“需要复核的候选事件”，不是自动进行责任认定。
- 不以人脸识别或真实身份识别作为必要功能。
- 不通过算法直接作出罚款、信用评价或其他对个人权益有重大影响的决定。
- 市民端不公开原始视频、清晰人像、连续个人轨迹或内部审计信息。
- 所有模拟数据和预生成演示事件必须显式标注。

## 3. 用户、终端与权限

| 体验 | 主要用户 | 主要任务 | 主要终端 |
|---|---|---|---|
| 市民用户端 | 访客、注册市民、商户与区域单位人员 | 登录前了解产品；登录后科普、地图、上报、进度、任务与申诉 | 手机优先，完整响应式 |
| 治理作业端 | 环卫、巡查、市/县区/街道审核与调度人员、AI/设备运维 | 移动作业、研判、派单、复盘、跨区域协同、系统配置 | 桌面 + 移动工作台 |
| 平台管理与执法协同端 | 超级管理员、账号安全管理员、依法具有相应权限的执法人员 | 账号权限与登录安全；线索、证据、身份、申辩与处理结果 | 桌面 + 必要移动页面 |

### 3.1 登录与分流

- Landing Page 永远公开，不强迫登录。
- 市民用户从 Landing Page 顶部直接注册或登录，登录后保持在同一端并进入个人首页。
- 工作人员从统一工作入口登录，根据角色进入治理作业端的桌面管理工作台或移动作业工作台。
- 超级管理员和执法人员通过受控入口进入第三端，但只看到各自被授权的模块。
- 城市治理介绍可以公开浏览；举报、补充材料和查询个人记录必须注册登录。后台仅向授权人员显示举报人的账号及身份信息。
- 后续可接入统一政务身份认证，同时保留受控的应急登录方式。

## 4. 网站总体结构

```text
烟踪智治（三端）
├─ 市民用户端
│  ├─ 登录前：Landing Page / 科普预览 / 规则与隐私 / 注册登录
│  └─ 登录后：市民首页 / 合规吸烟点 / 视频上报 / 文明任务 / 进度与申诉
├─ 治理作业端
│  ├─ 桌面工作台：证据总览 / 事件研判 / 治理调度 / 时空复盘 / 系统与模型
│  └─ 移动作业台：今日任务 / 导航 / 到场确认 / 清理取证 / 异常与历史
└─ 平台管理与执法协同端
   ├─ 平台管理：账号 / 角色 / 区域权限 / 登录审计 / 安全策略
   └─ 执法协同：线索 / 证据 / 身份核验 / 告知申辩 / 处理结果
```

## 5. Landing Page 设计

### 5.1 页面角色

Landing Page 是网站真正的首页，负责解释系统、建立信任并将不同用户引导到相应产品端。它不是后台 KPI 的公开复制，也不直接展示敏感实时监控内容。

### 5.2 顶部导航

桌面端采用透明到实色渐变的吸顶导航，移动端折叠为抽屉：

- 品牌标识：烟踪智治
- 锚点导航：产品机制、使用场景、平台角色、隐私安全、部署与合作
- 次级动作：查看演示
- 主动作：进入平台

滚动越过首屏后，导航背景由透明变为高对比实色，保持内容可读性。当前章节在导航中以细线或坐标刻度标识，不使用普通胶囊按钮堆叠。

### 5.3 长滚动章节

#### 第一幕：Hero——先交代产品价值

- 主标题建议：“让每一次发现，都有证据；让每一次治理，都有结果。”
- 副标题说明城市公共区域扔烟头动作监测、人工复核、环卫协同和执法线索流转，而不是宣称全自动定责。
- 两个行动入口：“查看如何运行”“进入治理平台”。
- 主视觉不是抽象蓝色飘带，而是一条由三帧画面、时间戳和轨迹形成的空间化证据链。
- 页面底部露出下一章节标题，明确告诉用户可以继续向下浏览。

#### 第二幕：为什么需要这套系统

- 使用城市道路、广场、公园、交通场站、商业街区、校园等真实公共场景图。
- 对比“只发现地面烟头”和“还原事件过程”的差别。
- 不堆砌夸张数据，重点解释传统方式在发现时间、事件复核和调度衔接上的断点。

#### 第三幕：一条事件如何完成闭环

采用横向或滚动驱动的五阶段叙事：

`捕捉 → 串联 → 研判 → 调度 → 复盘`

当用户滚动时，画面中央保持同一事件，周边依次出现目标框、三阶段关键帧、人工确认、移动工单和治理结果。该章节是整页最重要的产品演示，不做成普通五卡片列表。

#### 第四幕：证据链交互样例

- 三联画面：持烟、抛掷、落地。
- 共用毫秒级时间轴，而不是三张互不相关的缩略图。
- 可切换“原始画面 / 目标框 / 轨迹 / 系统推断”图层。
- 明确显示“候选”“已复核”“已驳回”等状态。
- 每个阶段显示独立置信度和证据缺失项，不使用单一总分掩盖不确定性。

#### 第五幕：不同角色如何协作

通过一条连续事件展示五类体验：市民或系统发现、审核员研判、调度员派单、环卫人员清理，以及满足条件时由执法人员依法处理。每个角色只展示其需要的信息，体现隐私和最小权限原则。

#### 第六幕：信阳区域使用场景

- 城市道路、背街小巷与商业街区
- 公园、广场和大型活动区域
- 车站、公交站等交通场站
- 景区、河岸与公共服务区域
- 校园、医院和机关单位周边

每个场景说明摄像头条件、可见性限制和适合的治理方式，避免暗示任何场景都能稳定识别。

#### 第七幕：从单次事件到长期治理

- 重复发生点
- 高发时间段
- 处置响应时长
- 治理前后趋势
- 设施和巡查调整建议

图表必须允许追溯数据来源，并说明样本量。趋势不足时显示“数据积累中”，不制造虚假增长率。

#### 第八幕：隐私、安全与责任边界

- 原始视频与公开展示分离。
- 普通展示自动遮挡人脸和敏感区域。
- 授权、访问日志、保存期限和删除机制。
- 候选事件须人工复核。
- 模拟数据、测试数据、真实数据具有明确标签。

该章节不能藏在页脚，应作为建立信任的主要内容。

#### 第九幕：部署与行动入口

说明可从一个县区或若干街道的少量摄像头开始试点，再根据验证结果扩展。最终 CTA 分为“市民注册/登录”和“工作人员入口”；工作人员登录后再按角色进入治理作业端或平台管理与执法协同端，避免首页堆放过多入口。

### 5.4 滚动与动效

- 动效用于解释事件状态变化，不用于制造无意义炫技。
- 三帧证据链可采用轻量 sticky scroll：文字继续滚动，证据画面保持并逐层叠加。
- 轨迹线、时间刻度和校验标记按阅读进度出现。
- 尊重 `prefers-reduced-motion`；关闭动效时内容仍然完整。
- 首屏避免大体积自动播放视频阻塞加载，可先显示海报帧并由用户选择播放。

## 6. 治理作业端：桌面管理工作台

### 6.1 总体框架

治理作业端采用同一账号体系和同一业务数据，在桌面呈现管理工作台、在手机呈现作业工作台。桌面工作台左侧保留五个一级入口，顶部提供区域切换与系统状态，中央为任务区，右侧按需要展开证据或操作面板。首页不再使用宣传轮播。

区域组织按“市级—县区—街道/乡镇—网格/点位”分层。账号只看到被授权区域；市级账号查看跨区域汇总，县区与街道账号处理本辖区事件，避免所有人员进入同一个无边界后台。

导航层级控制在两级以内。旧 18 页分别归入五个主入口：

| 新入口 | 吸收的既有功能 |
|---|---|
| 证据总览 | 原总览、治理态势、设备状态、工作看板中的重点待办 |
| 事件研判 | 告警中心、事件详情、轨迹回放、事件报表中的事件级内容 |
| 治理调度 | 任务池、调度记录、环卫资源 |
| 时空复盘 | GIS、区域热力、数据分析、治理效果 |
| 系统与模型 | 设备档案、模型与数据集、AI 阈值、用户、配置、审计 |

### 6.2 证据总览

- 第一优先级展示待复核、证据缺失、超时工单和设备异常。
- 中心区域展示最新候选事件三联帧，可直接进入研判。
- 所有总数均可点击查看构成，避免无法解释的大数字。
- 系统运行状态只显示影响业务的异常，详细技术指标收进系统与模型。

### 6.3 事件研判

采用“三栏证据工作台”：

- 左栏：可筛选事件队列，显示候选、待复核、已确认、已驳回。
- 中栏：视频播放器、三联关键帧、目标框、轨迹和同步时间轴。
- 右栏：模型观察、规则推断、证据完整度、人工结论及操作按钮。

确认或驳回必须填写结构化原因；高风险操作提供撤销窗口。若现场模型正在运行，应显示视频源、帧处理状态、排队任务和当前延迟，但不把单帧推理耗时冒充端到端延迟。

### 6.4 治理调度

- 以工单状态流为主：待派发、待接单、处理中、待复核、已闭环、异常。
- 地图用于位置与路线，不替代任务列表。
- 派单时同时显示距离、当前负载、班次和预计到达时间。
- 闭环对比清理前后照片、完成时间和异常说明。

### 6.5 时空复盘

- 地图与时间筛选联动。
- 支持按区域、时段、摄像头和事件状态查看。
- 区分“事件数量”和“摄像头覆盖/在线时长”，避免把监测强度差异误当成行为差异。
- 治理前后对比必须显示样本窗口、覆盖变化和缺失数据。

### 6.6 系统与模型

- 摄像头与视频源状态
- 模型版本、数据集版本和部署记录
- 阈值与图像增强配置
- 测试视频运行与结果回放
- 用户、角色和最小权限
- 审计日志、证据保存期限与隐私配置

AI 配置修改应显示影响范围，提供版本记录和回滚，不允许无痕覆盖。

## 7. 市民用户端设计

市民用户端不是治理作业端的简化复制，核心是实名可追溯的线索提交、进度反馈和治理服务。公开介绍无需登录，提交举报必须注册登录。

### 7.1 建议功能

- 查看信阳市相关环境治理规则、上报说明和区域治理信息。
- 通过手机摄像头录制短视频，或从本地选择已有视频，提交疑似扔烟头行为线索。
- 对视频执行时序行为分析，展示“正在分析 / 形成候选 / 未形成候选”等辅助状态。
- 拍摄或上传现场照片，用于补充烟头落地点、环境卫生状况和处理结果；照片不用于宣称识别出抛掷动作。
- 提交定位、视频、可选照片、问题类型和文字说明。
- 举报必须登录后提交，后台授权人员可以查看举报人的账号与身份信息。
- 用户可在“我的上报”中查询自己的记录，不提供匿名查询码。
- 对已完成事项进行反馈。
- 在不暴露个人与内部证据的前提下查看公开治理成果。

### 7.2 视频线索分析与上报流程

```text
打开上报页
→ 检查登录状态
→ 现场录制短视频 / 选择已有视频
→ 本地预览、裁剪时间范围或重新录制
→ 上传并执行时序行为分析
→ 显示持烟、疑似抛掷、疑似落地等阶段线索
→ 可选拍摄现场烟头或环境照片作为补充
→ 用户确认问题类型、位置和说明
→ 登录账号提交
→ 生成上报编号并进入“我的上报”
```

交互要求：

- 首次调用摄像头和麦克风前解释权限用途；默认不要求录音，视频可静音上传。用户拒绝摄像头授权后仍可选择本地视频。
- 自动读取定位前单独征得许可，也允许用户在信阳市地图上选择县区、街道和具体点位。
- 分析结果是研判辅助，不是提交门槛。未形成候选动作时，用户仍能提交线索并说明理由。
- 单张照片只显示为“现场补充材料”，不得出现“扔烟头动作识别成功”等误导文案。
- 视频质量过低时提示光线、距离、遮挡、镜头运动和持续时间问题，不只显示“识别失败”。
- 上传前提供隐私提醒，建议避免持续跟拍无关人员；必要时提供人脸和车牌自动模糊预览。
- 用户提交的纠错和标注可作为模型改进候选素材，但未经单独授权不得直接进入训练集。

### 7.3 上报详情与进度

进度节点建议为：

`已提交 → 待核验 → 已受理 → 处理中 → 已完成 / 不予受理`

- “不予受理”必须提供明确原因，例如位置不明、图片无法核实、内容重复或不属于处理范围。
- 举报用户只看到自己的处理进度、公开回复和必要的结果照片，不显示内部人员信息和完整证据链。
- 上报详情提供撤回或补充说明能力，但进入处理后的撤回规则需由管理制度确定。

### 7.4 隐私限制

- 不显示候选行为人的清晰图像。
- 不公开实时摄像头画面、轨迹或精确个人活动记录。
- 用户上传前明确告知用途、保存期限和可见范围。
- 公开成果以区域汇总和治理动作呈现，不做个人曝光。
- 举报人身份信息与举报内容分级展示：审核和管理角色可按权限查看，环卫作业人员原则上只看到完成任务所需的位置与现场信息。

## 8. 治理作业端：移动作业工作台

移动作业工作台属于治理作业端，不单独计算为第四个端。它采用移动 Web/PWA 核心体验，可在普通浏览器、微信和企业微信中打开；若后续建设小程序，应复用同一业务流程和接口，而不是维护互不一致的两套工单逻辑。

### 8.1 首页

- 今日待办、正在处理和即将超时任务。
- 最近任务距离及班次状态。
- 弱网或离线状态明确提示。

### 8.2 任务详情

- 地点、导航入口、问题类型和必要的现场参照图。
- 不向作业人员展示多余个人证据，只提供完成工作所需内容。
- 一键接单、到达、无法处理、完成。
- 清理前后拍照采用同角度辅助框，便于后续核验。

### 8.3 异常与弱网

- 上传失败自动保留本地草稿并支持重试。
- 允许填写“未发现烟头、地点受阻、需要其他资源”等结构化异常。
- 关键操作按钮满足单手操作，触控区域不小于 44×44 px。

### 8.4 容器兼容

- PWA 支持添加到桌面和基础离线缓存。
- 微信环境下处理相机、定位、文件选择和返回行为差异。
- 企业微信环境可预留组织身份和消息通知接入。
- 无论从哪种容器进入，工单状态和照片均来自同一后端数据源。

## 9. 视频输入与现场模型运行

### 9.1 两类输入

平台同时支持：

1. **固定摄像头实时流**：用于日常在线监测，可配置 RTSP 等视频源、监测时段、ROI 和模型版本。
2. **上传视频文件**：用于历史素材复核、模型测试、演示和故障排查。

两类输入必须进入统一的“分析任务”模型，统一记录来源、任务状态、模型版本、开始与结束时间、处理帧数、失败原因和输出事件，避免形成两套无法比较的结果页面。

### 9.2 实时流界面

- 摄像头列表与在线、离线、处理中、暂停状态。
- 当前画面与必要的目标框/轨迹图层开关。
- 端到端延迟、帧处理速率、排队情况和最近候选事件。
- 断流、重连、模型不可用和证据生成失败提示。
- 暂停分析不等同于关闭视频源，两种状态需分别表达。

### 9.3 上传视频界面

- 拖放或文件选择上传，显示格式、大小和时长限制。
- 上传、排队、分析、证据生成、等待复核、完成、失败等任务阶段。
- 允许选择模型版本和分析配置，但普通审核员使用安全默认值。
- 结果页使用与实时事件一致的三联关键帧、时间轴和人工复核界面。
- 同一文件重复上传时提示可能重复，但允许授权用户重新分析以比较不同模型版本。

### 9.4 现场运行保障

- 提供“试运行”入口，先检查视频解码、模型加载、存储空间和证据目录是否正常。
- 正式启动前展示输入源、模型版本和关键阈值摘要。
- 现场模型异常时可切换到明确标注的预生成事件，保证演示和培训不中断。
- 页面分别显示单帧推理耗时和端到端事件处理耗时，禁止混为一个“实时性能”数字。

## 10. 执法协同与约束机制

### 10.1 为什么不能只靠宣传提醒

仅靠页面提示和文明倡议不足以形成稳定约束。产品需要把“发现行为”连接到“及时清理、现场劝导、重复点位巡查和依法处理”，否则行为人没有明确后果，治理端也只能被动统计。

但平台本身不是执法机关，不能因为模型判断就自动罚款。信阳市现行市容环境卫生管理规则为乱扔烟头提供了治理依据，最终处理必须由市、县（区）有权限部门依照正式程序实施。

### 10.2 分级处置模型

```text
AI 或市民提交候选线索
→ 人工核验证据完整性
→ 环境清理与热点记录
→ 能够现场确认时进行劝导、责令停止或补救
→ 达到执法移送条件时转执法协同端
→ 有权限人员核验行为、身份和规则依据
→ 告知当事人事实、依据及陈述申辩渠道
→ 作出处理或不予处理决定
→ 结果回传治理平台并留审计记录
```

建议把处置分为四级：

1. **治理提醒**：热点提示、文明宣传、增设烟蒂收集设施和巡查安排。
2. **现场纠正**：由有权限的现场人员进行劝导、责令停止、清除或采取补救措施。
3. **执法线索**：证据、身份和适用区域满足移送条件时，进入执法协同端。
4. **依法处理**：由有权限部门决定是否处罚，平台记录告知、申辩、决定与执行结果。

### 10.3 身份与处罚边界

- 识别出扔烟头动作不等于识别出行为人的法定身份。
- 不使用人脸识别自动确定身份，也不从普通举报材料中自动推断身份。
- 无法可靠确认身份时，事件仍用于清理工单、热点分析和巡查调度，但不得生成个人处罚。
- 可以在实时告警后通知附近巡查或执法人员到场核实；身份确认与现场记录由有权限人员完成。
- 举报人账号信息与被举报对象身份是两类不同数据，不能混淆。

### 10.4 平台管理与执法协同端页面

- 待核查线索：按县区、街道、时限和证据完整度排列。
- 证据包：原视频、三阶段关键帧、时间轴、位置、设备信息、人工复核记录和完整性校验。
- 规则依据：根据事发区域和时间显示可能适用的规则，由执法人员确认，不由算法自动定性。
- 身份与现场核验：记录核验来源、人员、时间和补充材料。
- 告知与申辩：记录告知时间、当事人陈述、补充证据和复核意见。
- 处理结果：教育劝导、责令补救、不予处理、依法处罚或其他合法结果。
- 审计导出：所有查看、修改、移送和导出操作留痕。

平台管理模块另包含账号、角色、区域权限、会话、登录审计和安全策略。管理员只能发起密码重置，不得查看明文密码；平台管理权限与执法处理权限默认分离，授权和敏感操作必须留下审计记录。

### 10.5 设计依据与合规提示

- 《信阳市城市市容和环境卫生管理条例》禁止在公共场所乱扔烟头，并规定相应责令改正、补救和罚款机制；具体执行主体和程序以现行规则及主管部门要求为准。
- 《中华人民共和国个人信息保护法》要求个人信息处理遵循合法、正当、必要和最小范围原则；公共场所图像采集、行踪轨迹和自动化决策均需特别谨慎。
- 对个人权益有重大影响的决定不能仅由自动化决策作出，应保留人工说明、复核和异议渠道。

## 11. 视觉设计系统

本章说明视觉方向。可直接用于设计和前端验收的完整 Token、栅格、组件、动效、响应式、PWA、无障碍与证据可视化规则，统一以 [《前端视觉规范》](前端视觉规范.md) 为准。

### 11.1 视觉概念

方向名：**城市行为取证台 / Civic Forensics**。

设计语言来自现场取证、时间序列和城市基础设施，而不是云计算厂商的抽象科技飘带。

### 11.2 建议色彩

- 墨色 `#0B1320`：深色文本、导航与专业背景。
- 纸白 `#F4F1EA`：主要浅色背景，降低模板化冷白感。
- 余烬橙 `#FF6847`：候选事件、关键帧和风险动作。
- 信号青 `#38C8D4`：轨迹、实时状态和可交互信息。
- 苔绿 `#3E9B72`：人工确认后的闭环完成。
- 雾灰 `#A8B0B8`：次要信息与未启用状态。

颜色不是装饰标签：橙色只表示需要注意或尚未确认，绿色只表示完成或通过。

### 11.3 字体与数字

- 中文正文优先使用可稳定加载的无衬线字体。
- 事件编号、时间戳、坐标和指标采用等宽数字字体。
- 大标题保持克制，通过排版和留白建立气质，不使用发光描边。

### 11.4 图像与图形

- 优先使用经过授权的信阳城市公共空间场景或测试画面。
- 检测框、轨迹和隐私遮挡必须是可切换图层。
- 图标使用统一线性风格；避免拟物 3D 图标与扁平线性图标混搭。
- AI 生成图只能作为概念性氛围图，不能伪装成真实检测结果。

## 12. 响应式与可用性

- Landing Page 在桌面、平板和手机上重新排版，不进行整体缩放。
- 治理作业端桌面工作台和平台管理与执法协同端以 1440 px 宽度为主要设计基准，并支持 1920×1080 与常见笔记本屏幕。
- 低于桌面最小宽度时，治理作业端自动进入移动工作台或提示使用桌面端，不把完整管理界面缩成不可读小字。
- 所有图表提供文本摘要和空数据说明。
- 键盘可完成主要管理操作，焦点状态可见。
- 颜色对比、表单错误和状态变化不只依赖颜色表达。

## 13. 系统状态设计

每个数据页面都必须设计以下状态：

- 首次加载骨架
- 空数据与数据积累中
- 权限不足
- 视频源离线
- 模型未启动或推理队列拥堵
- 证据生成中
- 上传失败与重试
- 部分数据缺失
- 模拟数据模式

模拟模式应在全局顶部持续显示，并在导出内容中保留标记。

## 14. 推荐实施顺序

### 第一阶段：可投入试点的最小闭环

1. Landing Page 与角色入口
2. 事件研判
3. 治理调度
4. 环卫作业端
5. 摄像头和模型运行状态
6. 上传视频分析与任务结果
7. 执法线索流转、告知申辩和处理结果回传的最小闭环

### 第二阶段：扩大日常使用

1. 证据总览
2. 时空复盘
3. 市民上报与进度查询
4. 用户权限、审计和隐私配置

### 第三阶段：验证后扩展

1. 多点位部署
2. 更完整的数据分析和设施建议
3. 统一政务身份认证与跨区域账号体系
4. 企业微信或微信小程序接入
