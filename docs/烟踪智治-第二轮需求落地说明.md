## 二、逐项说明

### 1. 底部空白（"拉到底全是最底下空白"）
`EndShell.vue` 的 `.es-main` 底部一直留着 **74px** —— 那是给早已删除的"页面底部固定换端条"让位的，
换端条现在只挂在入口页（且不走这个外壳），这 74px 就变成所有非管理端页的一条纯空白带。

实测（市民端，1440×900）：滚动到底后内容底部空白 **82px → 16px**。

### 2. 顺手修掉的两个"空白等待"隐患
- **D-22 后端不可达时的假死**：`VITE_USE_API=1` 而 8000 没起时，Vite 代理会**挂起或返回 5xx**，
  `#/platform/overview?autologin=1` 会在路由守卫里 `await` 到 axios 的 15 秒超时 →
  **整页空白十几秒**；而且 `toFailure` 拿到的是 5xx（不是 status 0），
  第一轮做的"连不上就回退本地演示"根本不触发。
  修法：把 `/healthz` 纳入 Vite 代理 + 新增 `backendReachable()`（1.2s 超时、**校验响应是 JSON**
  而不是被 SPA fallback 骗过的 HTML、结果缓存 5s）；登录与数据仓库据此直接走本地模拟。
- **D-23 best.pt 预热阻塞服务**：`inference.warmup()` 原本是**同步**跑在 lifespan 里，
  而 uvicorn 先绑定端口再跑 lifespan → 出现"端口在监听，但任何请求（含 `/healthz`）都不响应"的窗口。
  实测 CPU 环境 `import ultralytics` 单次要 **47 秒**、进程内存涨到 1GB+。
  现在改为 `asyncio.create_task(to_thread(warmup))`，并新增配置项 `AI_WARMUP`（默认 1）。

> **重要实测结论**：模型加载完成后，单次推理只要 **27~30ms**（GPU）/ 3.3s（纯 CPU）。
> 之前观察到的"每次 30~90 秒"**全部是冷加载假象**。

### 3. 烟的一生 · 情绪共鸣剧场（互动剧情）
新组件 `frontend/src/components/citizen/SmokeStory.vue`：

- **四幕**：01 点燃 / 02 抛掷 / 03 清扫 / 04 渗透，每幕有主文案、旁白、角标微数据与满幅配图；
- **关键抉择**「如果当时……」，两个按钮：`随手一扔（污染继续）` / `走向吸烟区（结局改变）`；
- **两条分支结局**：A 给出河道打捞成本 ≈ 前端收集的 20 倍等数据；B 给出「谢谢你，让这座城市多了一分干净」
  + 文明积分 +20 / 碳减排贡献 +1；
- **分享海报**：canvas 现场绘制（底图 + 暗压层 + 主标语 + 数据卡 + 署名 + 落款），可保存到本地，
  不依赖任何后端；

### 4. 长者模式语音朗读
新组合式函数 `frontend/src/composables/useSpeech.ts` —— 把朗读做成**全局单播报器**：

- 整页连读 / 单条朗读 / 暂停 / 继续 / 停止 / 语速切换（很慢 / 慢 / 正常 / 稍快）；
- 高亮"正在朗读"的那一条（文章卡片与新闻卡片都支持）；
- 三处入口：科普页顶部**常驻朗读条**、每篇文章的「🔊 朗读」、每张新闻卡片的「🔊 朗读」；
- 工程细节：`getVoices()` 异步就绪监听、优先挑中文女声、`cancel()` 后旧回调用 runToken 丢弃
  （否则"下一段"会被推进两次）、改语速时从当前段重播、组件卸载必 `cancel()`、
  浏览器不支持时给出可见提示而不是按钮点了没反应；
- 互动剧场的"朗读这一幕"也接到同一个播报器上（`@speak` 事件），不会互相打断。

### 5. 地图演示导航
- `GaodeTileMap` 新增 `route` / `routeProgress`：按**折线累加长度**插值切分"已走/未走"，
  已走为高亮实线、未走为虚线，断点处画行进点；并新增 `setView(center, zoom)` 方法。
- 市民端 `buildRoute()` 按路网形态仿真折线（先拐上主路 → 沿主路 → 再折向目的地），
  转向文案由**叉积几何**推出（不是写死的"左转/右转"）。
- 导航开始时自动放大到 **z17 并居中到起终点中点** —— 校区尺度两点只差两百多米，
  z15 下路线只有约 60px，画出来根本看不见（第一次实现就踩了这个坑）。
- 面板贴在地图**右侧**竖排（放底部会遮掉 480px 高地图的一大半）；
  窄屏自动改为底部卡片式；演示 12 秒走完，同时显示真实步行时间与"仅提供方向参考"的免责说明。

### 6. 全域 GIS 地图细化
- `YzMapStage` 新增 `zones`（分级着色 + 区名 + 事件数 + 该区设备路数）与 `pois`
  （学校/医院/商圈/公园/公厕/站点，18×18 方块 + 单字图标 + hover 全称），
  并补了**千米网格**与**比例尺**；每个点位与兴趣点都带原生 `<title>` 提示。
- `GisView`：事件点位按摄像机**扇出**（同一台设备的多次事件不再叠成一个点，用稳定哈希做偏移，
  刷新不乱跳）、任务点/烟蒂设施/兴趣点分层；图层开关 3 → 7 个；
  地图点位 **10 → 66**，顶栏增加"在线设备 / 近 7 天事件 / 未闭环工单 / 烟蒂设施"四项概览。
- **踩坑**：分区色块原本画在街区地块**之下**，被不透明地块整片盖住（区名一个字看不到）→
  色块移到地块之上、区名文字放到最上层。

### 7. 总览"文字框重合"
实测根因：`.events-table` 实高 **213px**，而卡片可用高度只有 202px（230 − 28 上边距）
→ 最后一行**溢出卡片 12px**，并压到下方 `.overview-extra` 信息带上（实测重叠 2px）。

修法：行高 36 → 33、表头 31 → 30。修后实测：表格底距卡片底 **−4px**、距信息带 **14px**。

### 8. 上报接模型 → 当场 AI 报告 → 同步管理端 → 市民异议
**后端**
- `/public/ai/inspect` 重写为返回**结构化 AI 报告**：
  `verdict / verdict_label / verdict_tone / confidence / count / detections(含候选框) / stages(三段式推断标注) / evidence(证据链) / risk_notes / notice / timings(分步耗时) / device`；
- **判定口径修正**：必须检出 `cigarette` 才算"疑似烟头目标"。
  只检出 person/hand（画面里只有路过的人）不能算烟头线索，否则会出现假阳性（答辩会被追问）；
- 推理放到 `run_in_threadpool`，避免同步阻塞事件循环；
- `CitizenReport` 新增 `ai_report` / `ai_feedback` / `ai_feedback_at` 三列
  （`db.py` 加了**幂等补列**，旧库不用删就能升级）；
- 新增 `POST /citizen/reports/{no}/ai-feedback`（agree / reason / expect，只允许提交一次）；
- 审计新增 `REPORT_AI_CANDIDATE`（模型判定为候选时留痕，管理端"三端协同动态"立刻可见）
  与 `REPORT_AI_FEEDBACK`（市民异议留痕）。

**前端**
- 新组件 `components/citizen/AiReportCard.vue`，在**三处复用**：上报页「智能预检」步骤、
  提交成功后的记录卡、治理进度里的历史记录；
- 等待态有四步进度（上传素材 → 载入模型 → 目标检测 → 生成报告）+ 已等待秒数，
  超过 8 秒提示"模型首次加载约需 40~60 秒（仅第一次）"；
- 超时从原来的 **3.5 秒**提到 150 秒 —— 原来 3.5 秒超时后悄悄退回本地预检，
  用户根本看不到真实模型结论（这是"接了模型但感觉没接"的根因）；
- 失败时**仍允许提交**并说明已改用本地预检，不把用户堵死；
- 治理进度里每条上报都有「对 AI 判断有异议？」输入框 + 我不同意 / 判断合理两个按钮。

**实测**（上传一张烟头照片）：卡片渲染为 `st-done tone-ok`，结论「疑似烟头目标」，
置信度 **73.5%**，引擎 `best.pt · Ultralytics YOLO`，三阶段标注与证据链说明齐全，
耗时 `读取 0ms · 推理 3355ms · 合计 9429ms · 设备 cpu`。

### 9. 市民端手机 App 版
- 底栏从"5 个等宽 tab"改成 **App 风格 5 格**：首页 / 点位 / **监督拍照** / 科普 / 我的，

  **390 宽真机视口 iframe 预览**（iframe 视口就是 390，媒体查询自然生效，零 CSS hack）+
  「打开市民端 App」「收起预览」两个按钮。

用户反馈"点它进登录页和正式入口不一样"。已移除 `index.html` 的 `.yz-ends` 与 `end-switcher.css` 引用。

## 六、账号与数据存储说明（回答"存哪里、要不要现在上服务器"）

### 6.1 现在存在哪
| 数据 | 位置 | 说明 |
|------|------|------|
| 账号 | 后端库 `users` 表 | 当前是 **SQLite 单文件**：`backend/data/yanzong.db` |
| 口令 | 同表 `password_hash` + `password_salt` | **PBKDF2-SHA256，12 万次迭代，每人独立 16 字节盐**；**不存明文** |
| 登录态 | 前端 `localStorage` 的 JWT | HS256 签名，access 2 小时 / refresh 14 天 |
| 市民身份 | 手机号（`typ=citizen` 令牌） | 演示验证码固定 `123456`，**未接真实短信** |
| 操作留痕 | `audit_logs` 表 | 只增不改不删，管理端「审计日志」页可查 |
| 证据帧 / 闭环照片 | 本地目录 `backend/storage/` | 通过 `/storage` 静态映射对外，替代 MinIO |

### 6.2 要不要现在导入服务器？—— **建议先不导，等定好环境再迁**
理由：账号本身是 `seed.py` 一次性生成的演示账号，迁过去价值不大；
真正要迁的是"以后新建的真实账号 + 上报/事件/工单数据"。

### 6.3 如果要正式用，上线前必须做这几件事
1. **换数据库**：SQLite → PostgreSQL（配置已支持，只改 `DATABASE_URL`，
   `postgresql+asyncpg://用户:口令@主机:5432/yanzong`），单实例容器跑一个 PG 即可；

3. **收 CORS**：现在是 `http://127.0.0.1:*`，上线要收紧到真实域名；
4. **关掉演示后门**：`/api/v1/admin/reseed`（重建演示数据）、演示验证码 `123456` 要替换为真实短信服务或内部白名单；
5. **走 HTTPS**：Nginx/Caddy 反代 + 证书，前端 `VITE_API_BASE` 相应调整；
6. **初始账号**：上线后建 admin，其余按角色分配；不要再跑演示种子（或只跑摄像头与设施基础数据）。

### 6.4 需要你确认的信息（确认后我可以直接给部署方案/脚本）

- 有没有域名、能否签 HTTPS 证书；
- 打算用 PostgreSQL 还是继续 SQLite（单机小规模也能跑，但不建议长期）；
- 数据备份策略（每日 `pg_dump` + `storage/` 目录同步即可）。
