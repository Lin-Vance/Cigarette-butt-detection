# 烟踪智治 · 竞赛评委视角评审与优化建议

日期：2026-09-27  
评审对象：中国大学生计算机设计大赛 Web/软件应用方向、全国大学生数字媒体科技作品及创意竞赛  
评审立场：以当前工作区真实完成度为依据，不按规划功能当作已完成成果

## 1. 总体结论

这个选题具备较好的竞赛潜力：社会问题明确、AI 与 Web 结合自然、三端闭环具有真实应用逻辑，用户端又能形成科普与数字媒体表达。它比普通“智慧城市数据大屏”更有故事，也比单纯目标检测演示更接近完整产品。

但当前最大风险是**规划强、成品弱**：现有 Vue 工程只完成登录和总览，行为识别链路尚未形成完整可验证实现。如果直接以“三端城市治理平台”参加高水平竞赛，评委很可能认为范围过大、功能主要停留在设计稿、核心算法用目标检测指标替代行为识别效果。

评委判断不会以页面数量为主，而会集中追问：

1. 扔烟头动作识别是否真的运行？
2. 一条事件能否从视频输入走到研判、工单、清理和结果反馈？
3. 模型误报、隐私、身份与处罚边界怎么处理？
4. 哪些内容是学生团队真正完成的？
5. 是否有真实测试、用户反馈和可复现实验？

## 3. 对三个端的评价

### 3.1 市民用户端——最适合数字媒体竞赛展示

优点：

- Landing Page、科普、地图、行为视频上报和文明任务具有清晰公众叙事。
- 可以通过滚动动画、时间轴和移动交互解释复杂 AI，具备数字媒体传播价值。
- 正向设施地图和知识任务避免产品只剩“举报别人”。

风险：

- 如果最终仍是普通彩色宫格小程序，会缺乏艺术与交互辨识度。
- 积分和举报结合过重，会引发诱导追拍、刷量和伦理质疑。
- 单张照片与行为识别若再次混用，会被评委直接指出逻辑错误。

建议：把市民端作为数字媒体版本的绝对主角，用“一名市民从了解问题到看到治理结果”的连续叙事展示产品。

### 3.2 治理作业端——最适合 Web 软件竞赛证明工程能力

优点：

- 同一端兼顾桌面管理和移动作业，范围比拆成两个系统更合理。
- 证据研判、调度、移动闭环可形成完整业务状态机。
- 区域权限、视频任务和实时状态能够体现 Web 工程复杂度。

风险：

- 18 页全部铺开会稀释核心完成度。
- 若表格、图表和按钮仍使用静态模拟数据，评委不会认可为完整系统。
- 地图和统计如果没有数据来源、时间范围与覆盖说明，会被视为装饰性可视化。

建议：比赛版本优先做好证据总览、事件研判、治理调度和移动闭环四个模块，其余模块可展示但不抢演示时间。

### 3.3 平台管理与执法协同端——必要但不应抢主角

合并方向合理，能够减少端数量，并补齐账号安全和处罚流程。但必须做到：

- 平台管理与执法处理权限分离。
- 管理员只能重置密码，不能查看明文密码。
- 登录失败、异常设备、角色变化、数据导出均有审计。
- 执法模块只接收人工复核线索，不接受原始 AI 自动处罚。

比赛演示中展示“一次线索移送 + 一次账号权限审计”即可，不需要把它扩展成庞大的政务系统。

## 4. 中国大学生计算机设计大赛适配

### 4.1 建议参赛方向

优先选择“软件应用与开发”中的 Web 应用方向。2026 年官方大类包含软件应用与开发、人工智能应用、信息可视化设计等；但当年信息可视化及数媒相关大类存在“中国古代建筑成就”主题约束，本项目不适合为了参赛强行改成信息可视化作品。

### 4.2 评委最看重的内容

- 可运行的浏览器端系统，而非静态页面视频。
- 前后端数据流、权限、状态机、错误处理和部署说明。
- 核心算法如何接入业务，而不只是调用一个模型文件。
- 真实数据来源、测试方法、性能指标和隐私处理。
- 源代码、作品说明、用户手册和功能演示之间的一致性。

### 4.3 Web 竞赛的最佳演示主线

```text
实时摄像头或上传视频
→ 形成扔烟头候选事件
→ 人工查看三阶段证据并确认
→ 自动生成待派发工单
→ 移动工作台接单并上传清理结果
→ 市民端看到处理完成
→ 满足条件时移送执法协同
```

完整跑通这一条链，比展示十八个互不关联的页面更有竞争力。

截至当前日期，2026 年中国大学生计算机设计大赛官网已发布本届决赛相关结果信息；若团队尚未进入本届赛程，应按下一届准备并重新核对正式规则。官方还要求数据来源合规、不得侵犯隐私，公开地图需符合地图审核与来源标注要求。

## 5. 数字媒体竞赛适配

### 5.1 优势

2026 年全国大学生数字媒体科技作品及创意竞赛强调人工智能、数字媒体、数据可视化、移动应用、科普教育、社会服务、创意表达和实践价值。本项目的市民端与 Landing Page 和这些方向高度匹配。

### 5.2 推荐表达方式

- 以市民端移动体验为主体，而不是展示一串管理表格。
- 用原创的“帧—轨迹—证据—治理结果”视觉语言贯穿作品。
- 制作 90–150 秒核心演示片：问题出现、行为被识别、人工复核、清理完成、市民收到反馈。
- 展示可交互原型和真实可运行页面，不只提交剪辑视频。
- 科普内容必须有来源，地图、字体、音乐、图片、视频和 AI 生成素材必须记录授权与生成过程。

### 5.3 参赛纪律提醒

2026 数媒竞赛官方通知要求说明作品、文档、演示视频、素材知识产权和 AI 工具使用情况，每件作品只能申报一个赛道或类别。官方提交说明还包含对既往获奖作品重复参赛的限制，因此同一版本参加两个比赛前必须核对申报顺序和重复参赛条款，不能默认“一套材料到处投”。

## 6. 国赛竞争力必须补齐的五项硬证据

### 6.1 行为级验证

至少准备一组独立视频测试集，报告：

- 事件级准确率、召回率和误报数。
- 持烟、抛掷、落地三阶段成功率。
- 人—物关联正确率。
- 夜间、遮挡、多人、远距离和镜头抖动等失败案例。

不能继续使用目标检测 mAP 代替行为识别指标。

### 6.2 真实闭环

至少有一条事件真实走完分析、复核、派单、移动端处理和结果反馈，所有状态来自同一份后端数据，而不是每页各自写死。

### 6.3 可用性测试

邀请不同角色完成典型任务，记录成功率、耗时、错误点和改版前后变化。即使样本不大，也比“大家都觉得好看”更有说服力。

### 6.4 原创与合规档案

建立素材台账，记录图片、字体、图标、音乐、地图、视频、数据集、模型和 AI 工具的来源、授权和修改过程。

### 6.5 稳定演示方案

准备实时演示和离线兜底两套路径。兜底事件必须标记为预生成演示数据，不能伪装成现场实时识别。

## 7. 评委可能追问的问题

1. 你们识别的是烟头还是扔烟头动作？
2. 三阶段状态机在哪里运行，如何证明它有效？
3. 只有目标检测 mAP，为什么能声称识别完整行为？
4. 遮挡、多人和烟头落地后不可见时怎么办？
5. 为什么需要三个端，它们如何共享同一事件状态？
6. 识别出动作后如何确认行为人身份？
7. 为什么没有人脸识别还能形成处罚？
8. 视频、举报人信息和登录记录保存多久？
9. 地图、视频和视觉素材是否获得授权？
10. 系统哪些部分真正由团队实现，哪些使用了开源或 AI 工具？
11. 是否做过真实用户测试或区域试点？
12. 如果模型或网络断开，业务如何继续？

答辩材料必须提前逐题准备证据，不要只准备口头解释。

## 8. 最终建议

不要把竞赛目标设成“做完所有规划页面”，而应设成：

> 用一个真实、可运行、可复核的扔烟头事件，证明三端能够共同完成发现、研判、清理、反馈与必要的执法协同。

Web 版本以工程闭环取胜；数字媒体版本以市民端体验、科普叙事和原创视觉取胜。两套参赛材料共享系统，但叙事重点必须不同。
