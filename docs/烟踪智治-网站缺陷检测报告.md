## 1. P0 致命缺陷

### D-01 后端 CORS 白名单端口写错，导致 API 模式下全站业务接口 403

- **现象**：所有 `/api/v1/*` 请求返回 `403 Forbidden`，响应体为纯文本 `Invalid CORS request`。管理员登录、市民登录、后台 20 页、市民端全部不可用。
- **根因**：后端 CORS 白名单与实际前端端口不一致。

  ```java
  // backend-java/src/main/java/com/yanzong/config/WebConfig.java:11
  registry.addMapping("/**")
      .allowedOrigins("http://127.0.0.1:5184", "http://localhost:5184")   // ← 写的 5184
  ```
  ```ts
  // frontend/vite.config.ts:19
  server: { port: 5180, host: '127.0.0.1', ... }                          // ← 实际跑 5180
  ```

  Spring 的 CORS 处理对**不在白名单内的 Origin 会直接 403**，而且 `allowCredentials(true)` 时无法用通配符绕过。关键点在于：**即使走 Vite 代理（浏览器视角是同源），Vite 仍会把原始 `Origin: http://127.0.0.1:5180` 透传给后端**，因此代理并不能规避这个校验。
- **复现步骤**：
  1. `cd frontend && npm run dev`（起在 5180）
  2. 浏览器打开 `http://127.0.0.1:5180/auth.html#/auth?role=admin`，输入 `admin / 123456`
  3. 期望进入 `#/platform/overview`；实际停在登录页，提示 `Request failed with status code 403`
- **复现证据（curl 三连，已实测）**：

  | 请求 | Origin | 结果 |
  |------|--------|------|
  | `POST /api/v1/auth/login` | 不带 | `200` |
  | `POST /api/v1/auth/login` | `http://127.0.0.1:5184` | `200` |
  | `POST /api/v1/auth/login` | `http://127.0.0.1:5180` | **`403 Invalid CORS request`** |
  | 经 Vite 5181 代理 | `http://127.0.0.1:5181` | **`403 Invalid CORS request`** |
- **影响**：交付即不可用的**阻断级**问题。答辩现场若用默认配置启动，等于网站打不开。
- **修复建议（任选其一，推荐 1）**：
  1. 把 CORS 白名单与 `vite.config.ts` 的端口对齐并覆盖备用端口：
     `allowedOrigins("http://127.0.0.1:5180","http://localhost:5180","http://127.0.0.1:5181","http://localhost:5181")`
  2. 或者改用 `allowedOriginPatterns("http://127.0.0.1:*","http://localhost:*")`（仅开发环境），避免端口一变就挂。
  3. 顺带把 `server.port` 固定住（见 D-03 的 `strictPort` 建议），杜绝端口漂移。

### D-02 环卫角色进入管理端 → 路由守卫无限重定向 → 整页白屏

- **现象**：以环卫身份（`worker01`）访问 `admin.html` 的**任何**路由，页面完全空白（`document.body.innerText.length === 0`，`.ad-page` 数量 0），连本应有权限的"任务池"也打不开。
- **根因**：`frontend/src/router/index.ts:138-145` 的越权兜底目标，对该角色而言同样是越权页，形成死循环。

  ```ts
  if (!auth.isLoggedIn) return { name: 'login', query: { redirect: to.fullPath } }
  const name = String(to.name ?? '')
  if (name && !auth.allowedPageNames.includes(name)) {
    return { path: '/platform/overview' }   // ← 固定跳 overview
  }
  ```
  而 worker 角色的允许列表（`stores/auth.ts:92`）是 `['dispatch-pool','dispatch-records']`，**不含 `overview`** → 跳过去又越权 → 再跳 → 无限循环。
- **浏览器控制台原始输出（已实测捕获）**：
  ```
  [Vue Router warn]: Detected a possibly infinite redirection in a navigation guard
      when going from "/" to "/platform/overview". Aborting to avoid a Stack Overflow.
  [Vue Router warn]: Unexpected error when starting the router:
      Error: Infinite redirect in navigation guard
  ```
- **复现步骤**：
  1. `auth.html#/auth?role=worker` 用 `worker01 / 123456` 登录 → 正常进入 `worker.html#/worker`
  2. 地址栏改为 `admin.html#/platform/dispatch-pool`（或点 `auth.html` 页脚的"管理端"链接）
  3. 期望：被挡回或提示无权限；**实际：白屏**
- **实测四路由全部白屏**：

  | 目标 | 结果 |
  |------|------|
  | `#/platform/users` | 白屏（hash 停在原处，textLen=0） |
  | `#/platform/overview` | 白屏 |
  | `#/platform/dispatch-pool` | 白屏 |
  | `#/platform/audit` | 白屏 |

- **触发入口真实可达**：`AuthView.vue:207` 页脚有 `<a href="./admin.html">管理端</a>`，环卫工在登录页点一下就会白屏。
- **影响**：白屏无任何提示，用户只会认为"网站坏了"。同时暴露了路由守卫的兜底设计缺陷——**兜底目标没有保证"必然可达"**。
- **修复建议**：
  1. 兜底改为**该角色真正有权限的第一个页面**，并加"目标是否放行"的自检：
     ```ts
     const allowed = auth.allowedPageNames
     if (name && !allowed.includes(name)) {
       const fallback = PAGE_PATH_BY_NAME[allowed[0]]
       return fallback ? { path: fallback } : { name: 'login' }   // 无任何权限 → 回登录
     }
     ```
  2. 语义上更合理的是：**环卫角色不应被允许进 `admin.html`**（他本应待在 `worker.html`）。建议在守卫里对"角色-入口页"做一次匹配，不匹配就跳回该角色自己的端。
  3. 加一条兜底：`onError` 里捕获 `Infinite redirect`，至少给用户一个可见提示，别留白屏。

## 2. P1 高优先级缺陷

### D-03 `/api` 代理指向的是残缺的 Java 后端，`/storage`、`/ws` 却指向 Python 后端

- **现象**：前端代理配置把三类流量拆给了**两个不同的后端**，且其中一个只实现了约四成接口。
  ```ts
  // frontend/vite.config.ts:19-33
  '/api'     → 'http://127.0.0.1:8080'   // backend-java（Spring Boot）
  '/storage' → 'http://127.0.0.1:8000'   // backend（FastAPI）
  '/ws'      → 'ws://127.0.0.1:8000'     // backend（FastAPI）
  ```
- **实测接口覆盖率比对**（直连 8080，排除 CORS 干扰）：

  | 前端调用（`src/api/endpoints.ts`） | Java 8080 | Python 8000 |
  |-----------------------------------|-----------|-------------|
  | `/auth/me` | **404** | 401（存在） |
  | `/events/summary` | **404** | 401（存在） |
  | `/events/heatmap` | **404** | 401（存在） |
  | `/stats/hourly` | **404** | 401（存在） |
  | `/stats/areas` | **404** | 401（存在） |
  | `/stats/types` | **404** | 401（存在） |
  | `/stats/health` | **404** | 401（存在） |
  | `/users` | **404** | 401（存在） |
  | `/audit/logs` | **404** | 401（存在） |
  | `/admin/reseed` | **404** | 405（存在） |
  | `/public/cases/{no}` | **404** | 存在 |
  | `/ai/*` | **404** | 存在 |
  | `/workorders`、`/workorders/stats` | 200 | 存在 |

  → 探测的 14 个前端必需接口中，**11 个在 Java 后端 404**；Python 后端则**清单完整**（`backend/app/routers/` 里 `/events`、`/workorders`、`/stats`、`/users`、`/audit`、`/suggestions`、`/citizen/reports`、`/ai` 全部齐备）。
- **连带问题**：
  - `/storage` 指向 8000：只起 Java 后端时，**证据帧与闭环照片全部 404**（实测 8080 与 8000 的 `/storage/` 均为 404，需后端实际写入文件后才有内容，但 8080 侧**没有配任何静态资源映射**，`WebConfig.java` 只有 CORS）。
  - `/ws` 指向 8000：只起 Java 后端时，实时告警与工单推送**永远连不上**。
- **影响**：API 模式天然处于"半瘫"状态——数据接口走到 8080 会大面积为空，证据图与实时推送又依赖另一个后端。运维与答辩时极易误判为"网站有 bug"。
- **修复建议**：
  1. **先做技术选型收敛**：确定"到底用哪个后端"，然后让 `vite.config.ts` 的三条代理指向同一个端口。若 Java 是目标后端，需补齐上表 11 个接口与 `/storage` 静态映射；若 Python 是目标，把 `/api` 改回 `8000`。
  2. 统一后端 README 的端口口径（见 D-05）。
  3. 建议在 `frontend/README.md` 里加一张"后端选择对照表"，避免后续再被改乱。

  | `grep -rn "yz-ends" src/ *.html` | **0 处** |

- **额外发现（测试被放宽）**：`qa-ends.mjs:239-246` 会把换端组件数量打出来，但断言里**没有校验它**：

  note(after.path === 'worker.html' && after.hasGate, '点卡片真的换页到环卫端',

  面板上明明写着"跨端切换组件 **0 个**"却判 PASS，**回归被用例自己掩盖了**。
- **修复建议**：
  1. 判断这是有意删除还是误删。若是**误删**，把 `.es-cross` 与 `<nav class="yz-ends">` + `end-switcher.css` 补回 5 个 HTML。
  2. 若是**有意改造**（比如改用登录页/页脚链接换端），则须同步：
     - 把 `qa.mjs` 的换端条用例改为对新方案的断言；
     - 把 `qa-ends.mjs` 的 `ends` 计数**加进断言**（`after.ends >= 1`），防止再次静默回归；
     - 更新 `frontend/README.md`（见 D-05）；
     - 并且必须给窄屏补一个可用入口，否则手机端无法换端。

## 3. P2 中优先级缺陷

### D-06 管理员端在窄视口下不可用（390px 缩放到不可读）

- **现象**：`admin.html` 在 390×844 下，`FitShell` 把 1672×941 定宽画布整体等比缩到 390px 宽，字号实际渲染约 3–4px，**完全不可读**，且下方留出大片空白。
- **证据**：`shots/qa-20260928/admin-m-00.png`（对照 `citizen-m-00.png` / `worker-m-00.png` 均正常）。
- **说明**：管理端定位为桌面后台，不做完整响应式可以接受；但**当前是"缩成蚂蚁"而不是"提示请用大屏"**，观感上像崩版。
- **修复建议（低成本）**：给后台加一个窄屏兜底——`@media (max-width: 900px)` 时不缩放、改为提示"管理端请在 ≥1280px 宽屏使用"并提供一个"查看移动端/市民端"的跳转；或至少给画布设 `min-width` 并允许横向滚动。

### D-07 Service Worker 陈旧且必然注册失败

- **现象**：`public/sw.js` 仍是已删除的 landing 工程遗留：
  ```js
  const CACHE_NAME = 'yanzong-landing-v1'
  const CORE_ASSETS = ['./', './favicon.svg', './landing/civic-forensics-hero.png']
  ```
  `favicon.svg` 已删除、`landing/` 工程已删除 → `cache.addAll()` 必然 reject。
- **影响**：生产构建下 `main.ts:27-33` 每次加载都会尝试注册，install 静默失败（`.catch(()=>{})` 吞掉），离线缓存**从未生效**；`dist/sw.js` 里同样是旧内容（已实测）。
- **修复建议**：要么按当前多端结构重写 `CORE_ASSETS`（5 个 HTML + 必要资源），要么整个移除 SW 注册与 `sw.js`，别留一个"看起来有离线能力、实际从未工作"的模块。

### D-08 `manifest.webmanifest` 未被任何 HTML 引用，PWA 不可安装

- **证据**：`grep -c "manifest" dist/*.html` → 5 个 HTML **全部为 0**；`manifest.webmanifest` 有完整配置（图标、`start_url`、`display: standalone`）却无人引用。
- **修复建议**：在 5 个 HTML 的 `<head>` 加 `<link rel="manifest" href="./manifest.webmanifest" />`；若不做 PWA 就删掉该文件，避免死资源。

### D-09 `vite.config.ts` 注释误导："构建产物可直接双击打开"

- **现象**：`vite.config.ts:12` 写着"相对 base：构建产物可直接双击打开（file://）"，但实测 `dist/assets/*.js` 里**残留绝对路径 `/design-assets/...`**（`OverviewView-*.js`、`main-*.js`），`base:'./'` 只改写打包引用，改不动运行时字符串。
- **后果**：双击 `dist/admin.html` → 所有设计稿图片与 `/media/*` 全部 404。
- **修复建议**：把注释改成"**必须用本地静态服务打开**（`start-frontend.bat` / `preview-build.bat`）"，并说明原因，避免交付时被误导。

### D-10 API 模式下登录失败直接抛英文技术文案

- **现象**：`.env.local` 默认 `VITE_USE_API=1`，后端 403 时登录页显示 **`Request failed with status code 403`**（实测捕获原文）。
- **根因**：`api/client.ts:46-62` 的 `toFailure()` 只认 `error_code` 字段，后端返回的是**纯文本** `Invalid CORS request` 时落到 `SYS_HTTP_ERROR`，直接透出 axios 的英文 message。
- **修复建议**：给 `toFailure` 补一条按 HTTP 状态码映射中文文案的分支（403→"无权限或被服务端拒绝"、401→"账号或密码错误"、5xx→"服务端异常"），并把原始英文放进 `console` 而非界面。

### D-11 QA 用例文本过期，长期假红（3 条）

- **现象**：qa.mjs 稳定失败 3 条，但**不是功能缺陷**，而是断言里的文案没跟着实现改：

  | 用例 | qa.mjs 断言 | 实现现状 | 判定 |
  |------|-------------|----------|------|
  | 市民端上报表单 | 找 `button` 文本含 **"随手拍"**（`qa.mjs:393`） | 快捷入口按钮文本是 **"安全上报"**（`CitizenAppView.vue:542`）；"随手拍"只在一句**注释**里（:538） | 用例过期 |
  | 市民端文明打卡 | 找 `.task-copy button` 文本含 **"去打卡"**（`qa.mjs:446`） | 该按钮文本是 **"开始任务" / "已完成 ✓"**（:611-612） | 用例过期 |
  | 底部端切换条 | 找 `.yz-ends a` | 组件确实不存在 | **真实缺陷（见 D-04）** |
- **修复建议**：改用**稳定选择器**而非文案匹配（例如给按钮加 `data-testid="report-entry"`、`data-testid="checkin"`），从根上避免"改文案 → 用例假红"。这也符合工程里既有的教训（根节点签名要用挂载后不变的类名）。
