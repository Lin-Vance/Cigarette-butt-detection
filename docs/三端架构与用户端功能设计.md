# 烟踪智治 · 三端架构与用户端功能设计

版本：v0.1  
日期：2026-09-27  
状态：确认方向后的细化方案，不包含代码实现

## 1. 三端结论

产品最多建设三个端，并严格避免因角色增多而继续拆端：

| 端 | 使用者 | 核心职责 | 形态 |
|---|---|---|---|
| 市民用户端 | 访客、注册市民、商户、区域单位人员 | 了解、科普、查找合规吸烟点、视频线索上报、文明任务、进度与申诉 | 移动优先，桌面响应式 |
| 治理作业端 | 环卫、巡查、审核、调度、区域管理、设备与模型运维人员 | 移动作业、事件研判、工单调度、区域复盘、系统运维 | 同一端内含桌面工作台与移动工作台 |
| 平台管理与执法协同端 | 超级管理员、账号安全管理员、依法具有相应权限的工作人员 | 账号权限与登录安全；已复核线索、身份与规则核验、告知申辩、处理结果 | 桌面端 + 必要移动页面 |

以下内容不单独计算为端：

- Landing Page：市民用户端的未登录首页。
- 环卫移动工作台：治理作业端的移动形态。
- AI 与设备运维：治理作业端中的角色模块。
- 城市治理大屏：治理作业端的只读展示模式。

## 2. 市民用户端定位

市民用户端不应只是一个“举报工具”。它要让普通人知道为什么烟头会造成问题、哪里可以规范吸烟、怎样提交可信线索、治理结果如何反馈，以及个人可以怎样参与建设干净的公共环境。

用户端的价值顺序为：

`先理解 → 再便利 → 可参与 → 有反馈 → 能申诉`

不把“抓到多少人”当作市民端成功指标，而把知识触达、合规设施使用、有效线索、问题闭环和复发率下降作为主要指标。

## 3. 登录前：Landing Page

Landing Page 与用户端共用品牌、路由和设计系统，是市民进入平台前的背景与说明，不再建设独立官网项目。

### 3.1 顶部导航

- 品牌与当前区域：烟踪智治 · 信阳市
- 产品机制
- 烟头危害
- 合规吸烟点
- 治理进展
- 隐私与规则
- 注册 / 登录

“工作人员入口”放在次级位置，避免普通用户误入管理系统。

### 3.2 长滚动内容

1. **Hero**：让每一次发现都有证据，让每一次治理都有结果。
2. **为什么关注扔烟头动作**：解释静态烟头发现与行为证据链的区别。
3. **一条事件如何处理**：捕捉、研判、清理、必要时执法协同、结果反馈。
4. **烟头环境知识**：火灾隐患、清理成本、公共环境影响，内容需有来源。
5. **合规吸烟设施**：展示附近吸烟点和烟蒂收集设施的价值。
6. **市民如何参与**：学习、上报、完成文明任务、查看处理结果。
7. **隐私与权利**：实名上报的用途、被举报对象保护、人工复核与申诉。
8. **治理成果**：只展示脱敏汇总数据和真实闭环案例。
9. **最终入口**：注册 / 登录，旁边提供工作人员入口。

### 3.3 登录转场

用户登录成功后不跳往风格完全不同的系统，而是从 Landing Page 平滑进入个人首页。品牌导航收缩为移动端底部导航或桌面侧栏，保留用户已经建立的视觉认知。

## 4. 登录后：用户首页

### 4.1 首页结构

- 顶部：区域选择、全局搜索、消息通知、个人头像。
- 主视觉：本区域文明治理主题，不使用促销轮播。
- 核心捷径：视频上报、合规吸烟点、文明任务、科普学习。
- 附近设施：距离最近的合规吸烟点、烟蒂收集设施、开放状态和导航。
- 今日文明任务：知识学习、设施纠错、环境问题反馈等低风险任务。
- 治理进度：用户最近一次上报的当前状态。
- 本地科普：根据季节和区域推送火灾风险、烟头处理和规则说明。

### 4.2 底部导航

建议固定为五项：

1. **首页**：综合入口与个人进度。
2. **地图**：合规吸烟点、烟蒂收集设施与公开治理服务点。
3. **上报**：居中主按钮，录制/上传视频或提交现场卫生问题。
4. **任务**：科普任务、文明行动、我的贡献。
5. **我的**：上报记录、收藏、通知、积分、隐私与账号。

“上报”按钮视觉突出，但不能设计成鼓励追拍他人的猎奇按钮。首次进入先展示安全与隐私提示。

## 5. 用户端重点功能

### 5.1 扔烟头行为线索上报

核心素材必须是连续视频：

```text
选择现场录制或本地视频
→ 预览并裁剪关键时间段
→ 选择地点或自动定位
→ 系统分析持烟、疑似抛掷、疑似落地阶段
→ 用户补充发生时间与说明
→ 阅读隐私和真实性承诺
→ 实名提交
→ 在“我的上报”查看处理进度
```

- 单张照片不得显示“动作识别成功”。
- 未形成算法候选时仍允许提交，由审核员判断。
- 默认不采集音频；若视频自带音频，上传前允许一键静音。
- 建议用户在安全位置记录，不尾随、不拦截、不公开传播他人画面。
- 提交后只展示受理进度和公开回复，不展示内部完整证据或处理人员隐私。

### 5.2 现场卫生随手拍

该入口用于上报地面已有烟头、烟蒂收集设施损坏、垃圾积存等现场状态，不属于扔烟头动作识别。

- 拍照或相册上传
- 自动定位或地图选点
- 问题类型
- 数量/范围的简单描述
- 是否存在火灾或通行风险
- 处理前后结果反馈

页面必须用不同图标和文案区分“行为视频线索”和“现场卫生照片”，避免用户误解算法能力。

### 5.3 合规吸烟点与烟蒂设施地图

这是用户端非常实用的正向功能，不能只做举报：

- 附近合规吸烟点、烟蒂收集设施和距离。
- 营业/开放时间、现场规则、无障碍情况。
- 步行导航和收藏。
- 设施是否满溢、损坏或位置错误的纠错反馈。
- 地图明确区分“允许吸烟区域”“禁烟区域”“烟蒂投放设施”，避免把烟蒂桶误认为吸烟许可。
- 管理端审核后才能公开新增点位，防止用户随意标记。

### 5.4 科普中心

科普不是几篇长文章，而应形成可完成、可检索、可分享的知识产品：

- 60 秒知识卡：烟头火灾风险、环境影响、正确熄灭和投放方式。
- 图解流程：系统如何判断动作、为什么仍需人工复核。
- 常见误区：看到烟头不等于还原了谁丢弃；吸烟点不等于所有周边均可吸烟。
- 本地规则：以通俗语言解释适用区域、可能的纠正和处理方式，并链接官方原文。
- 情景问答：通过短题目学习“应该在哪里熄灭和投放”。
- 可信来源：每条健康、环境或法规知识标注来源与更新时间。

### 5.5 文明任务与积分

可以保留附件中的“任务”和“积分”思路，但目标是正向参与，不是鼓励监视或刷举报：

- 学完一组科普内容。
- 完成规则小测。
- 核对一个公开设施点位是否仍可用。
- 参加官方发布的清洁或宣传活动。
- 提交有效环境问题并被核实。

积分规则：

- 举报数量不直接进入公开排行榜。
- 同一区域、同一问题重复提交不重复计分。
- 举报奖励需在核实后发放，并设置每日上限。
- 不以现金高额奖励刺激用户追拍他人。
- 排行榜如保留，只展示知识学习、志愿活动等正向贡献，可选择匿名昵称。
- 积分优先兑换公益徽章、活动资格或合作公共服务权益，具体奖品由运营方决定。

### 5.6 我的上报与申诉

状态统一为：

`已提交 → 分析中 → 待复核 → 已受理 → 处理中 → 已完成 / 不予受理`

- 用户可补充视频、照片和文字。
- 受理前可撤回；受理后可申请撤回。
- 不予受理必须显示原因。
- 用户可对处理结果补充说明或申请一次复核。
- 不展示可能导致报复或围观的被举报对象个人信息。

### 5.7 治理动态与公开成果

- 本区域已清理问题数量、平均响应时间和重复发生点改善情况。
- 公开典型闭环案例，但必须脱敏。
- 不显示“抓获人数”等煽动性指标。
- 图表标注统计周期和数据覆盖范围，避免用监控多寡制造虚假区域排名。

### 5.8 个人中心

- 实名信息与认证状态
- 我的上报、补充材料和申诉
- 我的任务、学习记录和积分
- 收藏的合规吸烟点
- 消息偏好
- 隐私授权与数据说明
- 账号安全与退出

## 6. 治理作业端设计

治理作业端合并原环卫作业端与治理管理端，依靠角色权限和响应式布局区分工作场景，不维护两套互相割裂的产品。

### 6.1 桌面工作台

- 证据总览
- 事件研判
- 治理调度
- 时空复盘
- 系统与模型
- 用户举报审核
- 执法线索移送

### 6.2 移动作业工作台

- 今日任务
- 地图与导航
- 到场确认
- 清理前后照片
- 无法处理与异常原因
- 历史任务

### 6.3 角色裁剪

- 环卫人员只看到自己的任务及完成任务所需信息。
- 调度员看到人员、区域和工单，不默认查看完整敏感视频。
- 审核员查看证据和举报人信息，但不能修改设备模型。
- 设备/模型人员查看运行状态和配置，不默认查看举报人实名资料。
- 超级管理员负责账号、权限和审计，不替代事件审核或执法决定。

## 7. 平台管理与执法协同端设计

第三端把平台级账号安全和执法协同合并，但两种职责通过角色权限严格隔离。

### 7.1 平台管理模块

- 用户账号创建、导入、停用、解锁和注销流程。
- 角色、菜单、操作权限及市/县区/街道数据范围授权。
- 发起密码重置、强制退出全部会话和启用双重验证。
- 登录记录：时间、结果、IP/设备摘要、失败原因和异常风险。
- 在线会话、异常登录提醒和安全策略。
- 权限变更、数据导出和敏感操作审计。

安全底线：管理员不能查看任何用户的明文密码；服务端只保存带盐的安全密码摘要；忘记密码只能重置，不能“找回原密码”。举报审核员、调度员、设备运维和执法人员不会因为进入同一端而自动获得账号管理权限。

### 7.2 执法协同模块

- 待核查线索
- 完整证据包与校验状态
- 规则依据提示
- 身份与现场核验记录
- 告知、陈述与申辩
- 处理决定及结果回传
- 全流程审计

该模块不接受未经治理作业端人工复核的原始 AI 告警，也不允许算法自动生成处罚决定。

## 8. 对附件示例的取舍

### 值得吸收

- 城市/区域选择。
- 附近合规吸烟点。
- 文明任务、科普和个人记录。
- 移动端五项底部导航。
- 用户一眼能看到最近任务和处理进度。

### 不直接照搬

- 不使用“随手拍一张照片即可识别扔烟头”的表达。
- 不用举报数量做公开积分排名，防止刷量、误报和跟拍。
- 不采用五颜六色的通用小程序宫格作为最终视觉风格。
- 不把用户端做成宣传海报与空白任务页的组合，每个入口都必须有完整状态与反馈。
- 不把“附近吸烟区”简单等同于许可，地图必须说明区域边界、开放状态和规则。

## 10. 第一阶段优先级

第一阶段先保证用户端真正可用：

1. Landing Page、注册登录与个人中心。
2. 视频线索上报、现场卫生随手拍、我的上报和进度反馈。
3. 合规吸烟点地图与点位纠错。
4. 科普中心与基础文明任务。
5. 治理作业端完成举报审核、研判、派单和移动闭环。
6. 平台管理与执法协同端完成基础账号权限、登录审计、最小线索移送和结果回传。

积分兑换、复杂排行榜和大型活动运营放在第二阶段，避免首期范围失控。
