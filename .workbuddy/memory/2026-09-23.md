**坑 1 · 全局 `img { max-width: 100% }` 会毁掉设计稿**（已修）
登录页 `.feature-art` 实际 241×217，而所在 `.feature-card` 只有 230×204。
该图片本身是一张**整卡截图**（含背景、边框、图标和内嵌文字），真实 `.feature-title`
是精确叠在图片文字上对齐的。加了 `max-width` 后图片被压到 230px，图内文字与真实文字
错位 → 出现"重影 + 删线"的错误观感。
`smoke-admin/*/styles.css` 一律只有 `img { display: block }`，**没有任何 max-width**。
设计稿大量依赖"图片溢出容器"，前端 base.css **绝不能加** `max-width: 100%`。

**坑 2 · ECharts heatmap 的两处几何陷阱**（已修）
1. ECharts 自动 `pointSize` 取的是 `min(绘图宽/NX, 绘图高/NY)`，横向单元格之间会留缝，
   呈现出规则白点阵 → 必须**显式给 pointSize**（本例 14 > 单元格最小边长 8.6）。
2. 校园点位包围盒近似方形（实测 408m × 298m），而热力图绘图区是 428×190（2.25:1）。
   直接把经纬度线性映射到索引，圆形热斑会被拉成 ~2 倍横椭圆。
   → 需按「地面真实距离之比 = 绘图区像素之比」反推补足边长，再按**地面距离**（而非百分比）
   外扩 180m 边距，否则边缘热斑的晕圈会被裁掉。
   地面距离换算：`mPerLon = cos(lat)*111320`，`mPerLat = 110540`。
