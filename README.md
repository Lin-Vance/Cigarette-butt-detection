## 产品目标

- 项目目标是建设一个能够服务信阳市各区域日常治理的网站，不只是申报或答辩演示原型；校园仅作为可能的试点场景之一。
- 核心研究对象是“人扔烟头的动作与过程”，不是在单张图片中寻找烟头；香烟、手部和行人目标检测只为时序行为判断提供基础线索。
- 申报书、论文、PRD 和既有设计稿是需求与研究参考，不是必须逐字照搬的产品定义。
- 产品价值不是单纯展示识别数字，而是建立“发现—研判—调度—闭环—复盘”的可追溯治理流程。
- 网站应诚实区分模型观察、系统推断、人工复核和治理结果，避免把目标检测指标直接表述为完整行为识别准确率。

## 产品组成

平台严格控制为三个端：

1. **市民用户端**：Landing Page 作为未登录首页；登录后提供科普、合规吸烟点地图、短视频线索上报、现场卫生照片、文明任务、治理进度、个人贡献与申诉。
2. **治理作业端**：将环卫作业与治理管理合并为同一应用。桌面端面向审核、调度、区域管理、设备与模型运维；移动工作台面向环卫和巡查人员接单、导航、清理和闭环。
3. **平台管理与执法协同端**：面向超级管理员和授权执法人员。系统管理角色负责账号、角色、区域权限、登录审计与安全策略；执法角色负责已复核线索、身份与规则核验、告知申辩和处理结果。

公开官网与业务系统应在视觉上属于同一品牌，但信息密度和交互形态不同。市民用户必须登录后才能提交举报，后台可按权限查看举报人信息；普通用户不得查看他人的身份、人脸、原始视频或敏感轨迹，完整证据仅向授权管理与执法角色开放。

公开官网不单独算一个端，而是市民用户端的登录前状态。AI 与设备运维作为治理作业端中的专业角色模块；城市大屏只是治理作业端的展示模式。平台管理和执法协同共用一个端，但依靠角色权限保持职责分离。

## 信息架构

治理作业端保留既有功能，但重组为五个一级入口：

- **证据总览**：待复核事件、证据完整度、系统状态和重点待办。
- **事件研判**：视频回放、持烟/抛掷/落地三联帧、轨迹叠加、确认或驳回。
- **治理调度**：工单生成、派发、改派、超时升级及清理闭环。
- **时空复盘**：信阳市区域地图、时间规律、重复发生点和治理前后变化。
- **系统与模型**：摄像头、模型版本、阈值、用户权限、审计和基础配置。

既有 18 页的功能原则上保留，可作为这五个入口下的二级页面，不再让页数主导产品结构。

## 首页要求

- 使用可持续向下滚动的 Landing Page，而不是登录页或后台大屏直接充当网站首页。
- 顶部设置固定导航，并提供清晰的“进入平台”“查看运行机制”等行动入口。
- 页面通过多个连续章节完成叙事：产品主张、城市环境问题、运行机制、三段式证据链、产品角色、使用场景、治理与执法协同、隐私安全、部署方式和最终行动入口。
- 首页可以使用空间化视觉、滚动触发动画和场景化图片，但不能照搬腾讯云等商业云厂商模板。
- 视觉方向采用“城市行为取证台 / Civic Forensics”：强调时间、帧、轨迹、证据编号和可复核性，避免通用蓝绿玻璃智慧城市模板。

## 核心业务要求

- 支持真实或测试视频输入，并展示模型运行状态。
- 支持现场运行模型，同时允许使用明确标注的模拟数据或预生成事件进行演示和故障兜底。
- 候选事件需要经过人工复核后才能进入正式治理工单；算法结果不能直接等同于责任认定。
- 每起事件保存原始来源、关键帧、视频片段、时间戳、目标框、轨迹、推断阶段和人工操作记录。
- 工单闭环包含派发、接单、到场、清理前后照片、完成时间和异常说明。
- 默认数据规模采用真实区域试点口径，不使用与实际部署不符的虚构千级设备和千级日事件数字。
- 市民用户端支持调用手机摄像头录制短视频，也支持上传已有视频，用于提交疑似扔烟头行为线索。
- 行为识别必须利用连续视频中的时序信息；单张照片不能被表述为“识别出扔烟头动作”。
- 拍照功能仅用于补充现场卫生状况、烟头落地点或清理前后状态，不承担动作识别结论。
- 举报人必须注册并登录后提交，后台可按权限查看其账号与实名信息；举报人只能查看自己的提交记录。
- 自动识别只作为研判辅助，模型未形成候选事件时仍允许用户提交线索，由管理人员复核。
- 视频输入同时支持固定摄像头实时流和本地视频文件上传，两类输入进入统一的分析任务、证据生成和人工复核流程。
- 平台不得依据算法结果自动处罚。候选事件经人工复核后，可转为环境清理工单或执法线索；行政处理必须由有权限部门依法完成。
- 对可确认的乱扔烟头行为，平台支持记录责令停止、清除或补救、告知教育以及依法处理等结果；当事人身份不能可靠确认时，只进入清理、巡查和热点治理流程。
- 超级管理员可以创建、停用、解锁账号，分配角色与区域权限，强制退出会话并发起密码重置，但任何角色都不得查看用户明文密码。
- 平台只保存安全密码摘要；“忘记密码”执行重置而不是找回原密码。登录审计记录账号、时间、结果、IP/设备摘要和异常风险。

## 终端策略

- Landing Page：桌面与移动端完整响应式。
- 治理作业端：同一端内提供桌面管理工作台与移动作业工作台；桌面适配常见 1440p、1080p 与笔记本屏幕，移动端适配弱网和单手操作。
- 市民用户端：移动端优先，同时提供桌面访问；移动浏览器可调用摄像头录制短视频或拍摄现场照片。
- 治理作业端的移动工作台采用 PWA/H5，并预留企业微信和微信内打开入口；需考虑弱网、拍照上传失败重试和大尺寸触控目标。
- 平台管理与执法协同端以桌面为主，并为现场核验提供必要移动页面。

## 当前已确认决策

- 面向信阳市多区域真实日常治理，而非仅制作答辩原型或校园系统。
- 管理功能重组为五个一级入口。
- 接受明显改变现有蓝绿玻璃视觉风格。
- 后续需要真实或半真实测试视频，并需要现场运行模型。
- 市民用户端的核心上报素材是短视频或已有视频，拍照仅用于补充环境与处理结果。
- 举报人必须注册登录，后台可按权限查看举报人信息。
- 治理作业端的环卫工作台同时兼容普通浏览器、PWA、企业微信和微信内访问场景。
- 视频分析同时支持固定摄像头实时流和上传视频文件。
- 产品严格限定为市民用户端、治理作业端和平台管理与执法协同端；Landing Page 并入市民用户端。
- 平台支持处罚流程协同，但不得自动处罚；最终认定和处理由有法定权限的人员完成。
- 前端当前阶段先完成设计文档，不进入页面编码。
- 计算机设计大赛按 Web 方向准备；数字媒体大赛按移动应用或社会服务方向组织作品表达。
- 当前优先目标是先把响应式网站做出来，不因算法、设备或合作条件不足暂停前端建设。
- 当前没有可合法使用的真实扔烟头动作视频，没有可接入的 RTSP 摄像头和 GPU 运行环境，也没有政府、街道、环卫或学校合作证明。
- 第一阶段用户端采用响应式 Web/PWA，不并行开发微信小程序或原生应用。
- 所有因缺少真实视频、设备和试点而使用的数据、点位及事件必须显著标记为演示或测试内容，不得包装成真实落地成果。

## 待确认事项

以下事项均不阻塞当前响应式网站设计与开发，待具备外部条件后再确认：

- 市民实名注册采用手机号认证、统一政务身份认证或两者结合的具体方式。
- 用户举报是否只处理扔烟头行为，还是同时接受地面烟头等普通卫生问题。
- 是否拥有权威的吸烟点或烟蒂投放设施数据；未确认前仅使用标注清楚的演示点位。
- Logo、城市照片、地图、视频、字体与音乐的授权情况；未确认前建立素材台账并使用原创或明确可商用素材。
